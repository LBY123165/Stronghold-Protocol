- **账号列表 + 按用户名搜索**（`GET /api/admin/accounts?q=`）—— 绝不返回 passwordHash / salt / token
- **重置密码**（`POST /api/admin/accounts/password`）—— 至少 8 位，**清空该账号所有 token**（所有设备被登出）
- **封禁/解封**（`POST /api/admin/accounts/ban`）—— 封禁后 `login` 返回 `BANNED`、`authenticate` 直接跳过该记录（token 失效），数据保留可解封
- **删除**（`POST /api/admin/accounts/delete`）—— 不可恢复，用户名被释放可重新注册
- 前端在 `public/admin/` 加了「账号」区块（表格 + 搜索框 + 三个操作按钮，删除需再输一次用户名确认）

### 坑
- **账号名规则**：`shared/account.js` 的 `ACCOUNT_NAME_RE` 要求 **3–24 字符**且含至少一个字母或数字 —— `阿甲`/`贝塔` 这种 2 字中文名会被拒（`INVALID_INPUT`）。写测试要用 3 字名。
- **测试必须给每个 server 独立的 `accountsFile`**：默认是仓库的 `.cache/accounts.json`，不隔离会互相串号（`NAME_TAKEN`）。用 `mkdtemp` + `accountsFile` 选项。
- **维护模式会让 fetch 报 `fetch failed`**：emergency 门禁给普通 HTTP 加 `Connection: close`，fetch 的 keep-alive 连接池里那个连接已废。测试里加 `headers: { connection: 'close' }` 即可。
- admin 路由在 emergency 门禁**之前**处理，所以维护模式下后台仍可用 —— 这是设计意图（运维需要它）。

## 服务器动画偏移/不渲染的排查（对照 master 目录）
对照 `Stronghold-Protocol-master/`（fork 上游 0.2.4 线）与当前工作树（migrate-0.3.1）逐层比对，结论：**不是渲染代码问题**（`public/js/render/`、`public/js/battle/`、`shared/` 三处 diff 全为空，pixi-spine 版本一致，atlas 与 PNG 尺寸 674 个全部一致），问题在**素材与清单**：

1. **master 目录根本没有 `public/assets/`**（素材 gitignored，仓库不含）。两边 `data/assets.json` 除 `chars[*].skins` 外**逐字节相同**（`hash` 字段都是 `d885b22d8f78`，`stats` 也相同）。
2. **fork 的 manifest 多了 1294 个 URL**（1023 个 `assets/spine` 皮肤模型 + 271 个 `assets/char/skin_avatar`），来自 `tools/skins-inject.mjs` 注入的 `chars[*].skins` 块（master 没有 `skins` 字段）。这些文件**本地 `public/assets` 里 1303 个全部不存在**（skel/atlas 各缺 341、png 缺 617、mp3 缺 4、enemy icon 缺 4）→ 服务端实测这些路径 404。
3. **「偏移」的真正机制**：服务端 `server/http/assetViews.js` 的 `rewriteManifest` 给每个 Spine 模型算**一个模型哈希**（skel+atlas+贴图的成员哈希合并），skel/atlas/贴图三条 URL 共用同一 hash 段。pixi-spine 靠「atlas 与 skel 同目录、贴图在 atlas 同目录」定位。`enemy_9033_acdeer` 的贴图在磁盘上缺失 → 模型哈希算不出 → **skel 带 hash 段而贴图不带**（实测 skel `~a57127de…` / atlas `~91cbd0ab…` / 贴图无 hash），pixi-spine 按 skel 的目录找贴图就会找错/找不到 → 偏移或整块不渲染。
4. **`GAME_FILES` 多了 `'skins'`**（`public/js/ui/gameComponents.js`）→ 请求 `/data/skins.json` 实测 **404**（`data/` 下无此文件，master 无此项）。`useData` 把 `missing` 也算 ready，所以不会卡死对局，但每次开局都白请求一次 404。
5. fork 独有 `public/asset-cache-sw.js` + `public/js/asset-cache-worker.js` + `server/http/assetCache.js`（master 无）—— 离线素材缓存层，Service Worker 会拦截 `/assets/` 请求走 Cache Storage。服务器上若 SW 缓存了旧素材而服务端已更新，会放大「偏移」现象。
6. 排查方法（可复用）：起服务后用 node fetch 探 `http://127.0.0.1:PORT/data/assets.json`，看**服务端实际吐出的 URL 形态**（有没有 `~hash` 段、skel/atlas/贴图三者的 hash 段是否一致），再逐个 200/404 探三件套；比读代码有效得多。Git Bash 下 `curl` 会被代理环境变量劫持（返回 502），要用 node fetch 或 `curl --noproxy '*'`。
7. **修法方向**：① 补齐缺失素材（`node tools/setup.mjs` 或 rsync 传 `public/assets`）；② 或按 `docs/SKINS.md` 把皮肤做成**插件**（`plugins/stronghold-skins*`，master 的做法）而不是注入 `data/assets.json`；③ 清掉 `GAME_FILES` 里不存在的 `'skins'`。
